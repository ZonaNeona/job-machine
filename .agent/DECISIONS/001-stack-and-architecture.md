# ADR-001: Выбор стека, архитектуры и мультиагентного регламента

**Дата**: 2026-10-17  
**Статус**: Принято (Accepted)  
**Авторы**: Antigravity & User

---

## Контекст и проблема
Цель проекта: построить автоматизированный конвейер для привлечения 5–7 постоянных клиентов по 80 000 – 90 000 руб./мес. на разработку в нише LLM/AI, Telegram-ботов и автоматизации.
Над проектом попеременно работают разные ИИ-модели и агенты (Antigravity/Gemini, Claude 3.5 Sonnet / Opus, DeepSeek, GPT-4o, Cursor).
Требовалось:
1. Выбрать архитектуру Command Center (HQ), устойчивую к смене окружения.
2. Исключить рассинхронизацию контекста между разными агентами.
3. Обеспечить быстродействие интерфейса и надежную работу с парсерами.

---

## Решение

### 1. Архитектура приложения
- **Веб-интерфейс**: React 19 + Vite + Tailwind CSS v4 + Lucide Icons в папке `web-app/frontend`. Порт **5173**.
- **Бэкенд**: Python FastAPI + SQLAlchemy 2.0 ORM + Pydantic v2 в папке `web-app/backend`. Порт **8000**.
- **База данных**: SQLite (`job_machine.db`) для локальной разработки с полной готовностью миграции на PostgreSQL при развертывании в облаке.
- **ИИ-слой**: OpenRouter API (`ai_service.py`), позволяющий переключаться между Claude 3.5 Sonnet, DeepSeek V3 и GPT-4o через один ключ.

### 2. Мультиагентный протокол (Agent OS)
- **Точка входа**: `AGENTS.md` в корне.
- **Стандарты и инварианты**: `.agent/RULES.md`.
- **Системная карта**: `.agent/ARCHITECTURE.md`.
- **Живой реестр задач**: `.agent/CURRENT_SPRINT.md`.
- **Журнал передачи смены**: `.agent/HANDOVERS/`. Каждый агент обязан сдавать смену по шаблону `TEMPLATE.md`.
- **Единый источник бизнес-данных**: папка `assets/` (резюме, коммерческие предложения, кейсы, шаблоны откликов).

---

## Последствия
- Любой агент (GPT, Claude, DeepSeek) при старте считывает `AGENTS.md` и моментально понимает текущий статус без потери контекста.
- Никакой агент не может случайно сломать зафиксированные порты (8000 и 5173) или структуру базы данных.
- Все расценки и кейсы согласованы и зафиксированы в `assets/`.
